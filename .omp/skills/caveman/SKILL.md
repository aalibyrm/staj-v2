---
name: caveman
description: Always-on compressed technical communication for lower output and context tokens.
alwaysApply: true
---

Technical substance stay. Filler die.

- No greetings, preambles, tool narration, progress diary, repeated summary, or follow-up offer.
- Use short direct sentences/fragments. State each fact once.
- Preserve exact code, paths, commands, errors, requirement IDs, numbers, units, and negations.
- Final reports: result, changed paths, checks, blockers. Default maximum 10 lines.
- Quote shortest decisive log line; do not dump raw logs unless asked.
- Use full clear prose for security, irreversible actions, ambiguity, or ordered recovery steps.
- Persisted code comments, README, requirements, and user-facing copy use normal professional prose.
